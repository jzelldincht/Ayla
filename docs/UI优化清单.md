# Ayla 界面优化清单（截图采集过程中发现）

> 来源：2026-09-18 实机截图采集（20 张真实界面截图）过程中的观察与代码核对。
> 优先级：**P1** 影响功能可用性/一致性，建议本轮修；**P2** 体验与观感优化；**P3** 可选打磨。

---

## P1 · 建议本轮修复

### 1. 设置页缺少「验证连接」入口
- **现象**：首启引导的「配置 AI 服务」步有「验证连接」按钮（当场校验地址/模型/密钥），但设置 → AI 服务 页没有。
- **影响**：用户在设置里改 Key、换服务商、改模型后无法即时验证，只能等一次真实翻译失败才发现配置错误；错误反馈链路变长。
- **证据**：`settings-ai-zh.png` / `settings-ai-en.png`（页面仅三行配置 + 隐私提示）；代码核对：`src/settings/App.svelte` 无验证调用。
- **建议**：在 AI 服务组底部加与引导页同款「验证连接」按钮：调用既有 `verify_connection` 命令（已支持缺省用已存值），行内显示「✓ 验证成功 / ✕ 失败原因」，可重试。

### 2. 英文界面下目标语言下拉显示中文语言名
- **现象**：界面切到 English 后，面板顶栏目标语言下拉仍显示「英文」「中文(简体)」等中文名。
- **原因**：配置 `translation.defaultTargetLang` 存的是中文标签字符串，UI 直接回显该字符串。
- **影响**：英文（及其他七语）用户看到的是看不懂的中文词，违反 i18n 一致性；我出商店截图时只能用「互译」模式绕开这个下拉。
- **证据**：`panel-input-en.png`（英文 UI + 中文下拉）。
- **建议**：显示层增加映射——把存储的中文标签映射到 `DIRECTED_TARGET_LANGS` 的 code，再用 i18n 目录渲染该语言在本界面语言下的名称（如 EN：Chinese (Simplified) / English / Japanese…）。存储格式保持不变（向后兼容），无需配置迁移。

### 3. 「长文整段阈值」在全部流式模式下未禁用
- **现象**：译文呈现=全部流式时，该阈值不生效，但输入框仍可编辑；同一页的「自动翻译延迟」在自动翻译关闭时是正确置灰的（`disabled` 绑定），两处行为不一致。
- **影响**：用户会误以为阈值在当前模式下生效（desc 虽写了「仅分档呈现下生效」，但控件外观无提示）。
- **证据**：`settings-translation-zh.png`；代码核对：阈值输入框无 disabled 绑定（`App.svelte`），延迟下拉第 558 行有 disabled 绑定。
- **建议**：跟随「译文呈现」联动禁用阈值输入框（呈现=分档时启用），或保持可编辑但加置灰态 + 更强的 desc 提示。

### 4. 截图遮罩层无屏上操作提示
- **现象**：按 Alt+S / Alt+D 后整屏变暗进入框选态，但屏幕上没有任何文字提示（只有拖拽过程中的「宽 × 高」尺寸标签）。
- **影响**：首次使用者面对暗屏不知道该拖拽选区，也不知道 Esc 可取消；这是截图翻译链路的第一触点，教学价值高。
- **证据**：`capture-mask-zh.png`（全屏暗化，无提示文字）；代码核对：`src/mask/App.svelte` 仅有尺寸标签与 Esc 逻辑，无提示文案。
- **建议**：在遮罩顶部（或光标附近）显示一行本地化提示：中文「拖拽选择区域 · Esc 取消」/ 英文「Drag to select · Esc to cancel」，随 UI 语言切换；可设为低透明不干扰。

## P2 · 体验与观感优化

### 5. 剪贴板开关的 tooltip 遮挡输入框文字
- **现象**：鼠标悬停顶栏剪贴板图标时，tooltip「开启后，自动翻译新复制的内容」浮在输入框文字上方。
- **影响**：遮挡内容、打断阅读（截图采集时实际发生）。
- **建议**：tooltip 移至图标下方/右侧，或压缩为短句（如「自动翻译新复制内容」）。

### 6. 输入框高度拖拽把手不易被发现
- **现象**：原文输入框右下角仅有极细的斜纹把手（textarea 原生 resizer），视觉上几乎不可见。
- **影响**：「拖动输入框高度并被记忆」是我们已实现的能力（用户明确要求），但发现率低。
- **证据**：`panel-input-zh.png` 右下角把手。
- **建议**：hover 时把手加深/放大，或首次出现时给一次性提示（tooltip 式），或提供设置项说明。

### 7. 译文 wash 卡片在短内容时仍填满剩余高度
- **现象**：窗口 700 高、译文仅 3 行时，浅蓝 wash 块仍从译文标题下方一直铺到面板底部（约 380px 高），大片色块内只有顶部几行字。
- **影响**：视觉上偏空；长文场景无影响。属设计取向问题（「区域已就绪」的语义 vs 内容贴合）。
- **证据**：`panel-input-zh.png`。
- **建议**（可选）：wash 随内容高度增长（下限 84px、上限为可用高度），下方留白；或维持现状并在文档中说明「译文区常驻底纹=可复制区域」。

### 8. OCR 识别文本的轻量后处理
- **现象**：截图识别的原文保留 OCR 引擎原始输出，存在：破折号 `—` 被识别为 `_`、拉丁词跨行断开（`Win dows`）、行尾断行未合并（一句话被拆成多行）。
- **影响**：识别原文可读性下降；译文质量受连字符/断行干扰（译文中出现多余空格断词）。
- **证据**：`panel-ocr-zh.png` / `panel-ocr-en.png`。
- **建议**：对 OCR 结果做轻量规整：合并行尾断词（`-` 结尾 + 下一行小写开头）、CJK 行间软换行合并、常见符号归一（`_`→`—` 仅在上下文明确时）；保留原文可编辑性。

## P3 · 可选打磨

### 9. 快捷键页说明文案五行重复
- **现象**：五个快捷键行都显示同一句 desc「录制式改键：冲突自动回退并通知」。
- **建议**：改为分组级说明（页首一行），各功能行只留键帽 + 「修改」。

### 10. 引导页 API Key 输入框占位符易误解
- **现象**：首启未配置时，Key 输入框占位符为 `sk-••••••••••••••••`，看起来像"已填入的密钥"。
- **建议**：占位符改为 `粘贴 API Key`（或加「未配置」角标），与设置页文案保持一致。

### 11. 设置页缺少「恢复默认值」
- **现象**：全部设置项无一键还原入口；用户误改后只能逐项改回或删配置文件。
- **建议**：通用组加「恢复默认设置」（二次确认），后端按出厂默认重写（引导完成状态与 API Key 保留）。

## 建议的执行顺序

1. **P1-1 设置页验证按钮**（中等工作量，闭环配置体验）
2. **P1-2 目标语言名 i18n**（中等工作量，影响所有非中文用户 + 商店截图质量）
3. **P1-4 遮罩提示语**（小工作量，链路首触点）
4. **P1-3 阈值联动禁用**（小工作量，一致性）
5. P2 项按需（tooltip 位置、把手可见性、wash 贴合、OCR 后处理）
