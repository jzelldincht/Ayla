## 1. 背景与问题

用户在日常使用 Windows 时，经常需要在任意软件（编辑器、浏览器、聊天工具、游戏等）中理解外语内容或将中文译出。现有做法是复制文本、切换到网页翻译器、粘贴再翻译，流程割裂且打断心流；游戏、图片内的文字更是无处下手。

已有开源方案 pot-desktop 验证了"全局快捷键 + 轻量翻译面板"的交互范式，但其功能面宽（23 个翻译服务、TTS、生词本、插件系统、跨平台），且基于已停维护的 Tauri 1.x。本项目只需其中约 20% 的能力：单一 AI 翻译服务（现阶段 DeepSeek）、仅 Windows。

因此需要一个全新的、托盘常驻、界面简洁美观大方的 Windows 桌面应用 **Alya**：以全局快捷键触发取词 / 输入 / 剪贴板监听 / 截图四类入口，统一经由 AI 翻译产出译文。技术路线已定（见 docs/adr/0001：全新 Tauri 2 应用，借鉴 pot 已验证机制，不 fork、不复制 GPL 代码），本文只描述行为需求，不涉及实现设计。

## 3. 非目标

v1 明确不做以下内容（超出即为扩大范围）：

1. 非 Windows 平台（macOS / Linux）。
2. 第三方翻译平台接口（Google / DeepL / 百度等）；v1 仅 AI 翻译，现阶段仅 DeepSeek（经 OpenAI 兼容协议，接口地址可指向其他兼容服务）。
3. TTS 朗读、生词本、收藏夹。
4. 插件系统、外部 HTTP 调用服务（作为服务端被调用）。
5. WebDAV / 云端配置备份与同步。
6. 自动更新（v1 手动升级）。
7. 多语言界面（v1 界面仅简体中文）。
8. 放大镜、像素拾取器（截图辅助工具）。
9. 历史记录、术语表（v1 不含历史记录，亦不持久化翻译原文与译文）。
10. 多套 AI 服务配置的保存与快速切换（v1 仅一组全局生效的接口地址 / 模型名 / API Key 配置）。
11. 源语种的显式检测展示（互译的判向由提示词语义约定，界面不展示"检测到的语种"）。

## 4. 用户场景

**S1 开发者读英文文档（划词翻译 / 互译）**
开发者在 VS Code 中读到陌生英文段落，选中文本按下快捷键，翻译面板在鼠标附近弹出，译文流式浮现，全程手不离键盘、视线不离文档。

**S2 与日方客户沟通（定向场景）**
用户需要把中文回复译成日文。在翻译面板将活动场景一键切为定向、目标语言选"日文"，此后无论划词、输入还是复制，译文一律是日文；次日重启应用，仍是定向（活动场景持久化），但目标语言回落到设置页默认值。

**S3 本地化整理资料（剪贴板监听）**
译者开启面板左上角的剪贴板监听开关后，专注浏览原文 PDF，逢段落 Ctrl+C，翻译面板即自动给出译文，无需任何额外按键。

**S4 游戏内文字看不懂（截图翻译）**
玩家在游戏中看到不明俄文提示，按截图翻译快捷键，屏幕变暗，框选那行字，松开鼠标，面板中同时出现识别出的原文与流式译文。

**S5 从图片提取文字（截图识别，无需 API Key）**
用户只想把扫描图里的一段话变成可编辑文本。按截图识别快捷键框选后得到纯文字结果；此功能离线完成，不需要配置 API Key。

## 5. 功能与业务规则

> 术语遵循 CONTEXT.md：互译、定向、活动场景、目标语言、划词翻译、取词、输入翻译、剪贴板监听、截图识别、截图翻译、翻译面板。
> 既定技术约束（引自 request.md / ADR-0001，作为边界条件而非设计决策）：Tauri 2 全新应用；仅 Windows；OCR 采用系统引擎 Windows.Media.Ocr（离线）；翻译服务走 OpenAI 兼容协议、流式调用。

### FR-1 产品形态与生命周期

- FR-1.1 产品名为 **Alya**；v1 界面仅简体中文。
- FR-1.2 主题提供亮色 / 暗色 / 跟随系统三种，出厂默认"跟随系统"。
- FR-1.3 应用常驻系统托盘，无常驻主窗口；关闭翻译面板只是隐藏，应用继续驻留；彻底退出仅经托盘菜单"退出"。
- FR-1.4 单实例：重复启动不产生第二个进程，唤起已有实例，唤起行为为呼出输入翻译面板（Q8 已裁决）。
- FR-1.5 提供"开机自启"开关，出厂默认关。

### FR-2 双场景模型（互译 / 定向）

- FR-2.1 **互译**：自动判向的翻译场景，中文→英文、非中文→中文；判向规则由提示词语义约定（见 FR-2.5），不由界面选择。
- FR-2.2 **定向**：将文本译向一个明确指定的**目标语言**，使用带 {{target}} 占位符的提示词模板（已裁决的优化稿见 FR-2.6）。
- FR-2.3 **活动场景**：全局唯一、持久化记忆的当前场景（互译或定向）；所有触发入口（划词、输入、剪贴板监听、截图翻译）共用；出厂默认互译；应用重启后保持上次的活动场景。
- FR-2.4 活动场景切换途径：(a) 翻译面板内一键切换；(b) 全局热键 Alt+W 在互译与定向间二值切换；(c) 托盘菜单展示当前活动场景并可切换。切换立即对后续所有翻译生效，不影响正在进行的翻译。
- FR-2.5 **互译提示词（业务基线；2026-08-26 经用户批准在原始版本上追加"防乱码"规则行，其余保持逐字不变；再次修改需重新评审）**。其中 `{{text}}` 为待译文本占位符，调用时替换为完整原文：

```text
你是无情的翻译机器。无论输入是单词、短语还是句子，你都必须直接输出翻译结果，绝不做任何解释、评价或反问。

翻译规则：
- 如果输入文本是中文 → 翻译为英文
- 如果输入文本不是中文（包括英文、代码、混合内容等） → 翻译为中文
- 若无法绝对确定语种，默认视为非中文，直接翻译为中文
- 若输入不含可识别的自然语言内容（如乱码、无意义符号），原样输出输入内容，不做猜测性翻译

现在，立即翻译以下文本，只回复译文：
{{text}}
```

- FR-2.6 **定向提示词模板（用户裁决后的优化稿 v2，已裁决 Q1）**：角色设定与互译一致，翻译规则改为译向目标语言；新增对"源内容不可识别"的处理规则（用户评审意见：原建议稿缺少该分支）。`{{target}}` 调用时替换为目标语言名称（如"中文(简体)"、"英文"），`{{text}}` 替换为完整原文：

```text
你是无情的翻译机器。无论输入是单词、短语还是句子，你都必须直接输出翻译结果，绝不做任何解释、评价或反问。

翻译规则：
- 将以下文本翻译为{{target}}
- 若输入不含可识别的自然语言内容（如乱码、无意义符号），原样输出输入内容，不做猜测性翻译

现在，立即翻译以下文本，只回复译文：
{{text}}
```

- FR-2.7 **目标语言**：设置页保存默认值（出厂默认"英文"），并提供可选语言清单（首批清单见第 9 章 Q5 裁决）；翻译面板下拉可临时切换。临时切换仅当前运行期间有效，不回写设置页默认值；应用重启后面板下拉回落到设置页默认值。

### FR-3 入口一：划词翻译

- FR-3.1 交互流：用户在其他软件中选中文本 → 按全局快捷键（出厂 Alt+Q）→ 应用执行取词（模拟复制获取选中文本）→ 翻译面板在鼠标附近弹出（不得遮挡所选内容所在区域，具体定位策略由 UI/UX 设计规范定义）→ 面板展示原文，并按当前活动场景流式输出译文。
- FR-3.2 未选中任何文本或取到的文本为空白：不弹出翻译面板，给出一则系统通知"未获取到选中文本"。
- FR-3.3 取词失败（模拟复制未返回内容或超时）：同 FR-3.2 表现，通知说明未能获取文本。
- FR-3.4 触发时尚未配置 API Key：不执行翻译，转入首启引导 / 配置引导（见 FR-11.4）。

### FR-4 入口二：输入翻译

- FR-4.1 交互流：按全局快捷键（出厂 Alt+E）→ 翻译面板以输入模式出现，焦点落在原文输入区 → 用户输入文本 → 回车提交 → 按活动场景流式输出译文。
- FR-4.2 原文可编辑：译文产出后原文区仍可编辑，修改后再次回车或点击翻译控件即重新发起翻译，译文区被新一轮结果替换。
- FR-4.3 原文为空或纯空白时回车：不发起请求，界面无错误。
- FR-4.4 未配置 API Key：同 FR-3.4。

### FR-5 入口三：剪贴板监听

- FR-5.1 开关存在于三处且状态实时同步：翻译面板左上角开关、托盘菜单勾选项、设置页开关。
- FR-5.2 开启后，监测到系统剪贴板出现新文本内容时，自动按当前活动场景发起翻译并在翻译面板展示（面板若处于隐藏状态则弹出展示）。
- FR-5.3 开关状态持久化：应用重启后保持上次状态（出厂默认关）。
- FR-5.4 非文本剪贴板内容（图片、文件等）被忽略：不触发翻译、不报错、不打断监听。
- FR-5.5 剪贴板内容未变化（重复读取到相同文本）不重复触发；同一新文本仅在其成为"新复制内容"时触发一次。
- FR-5.6 关闭开关后立即停止响应剪贴板变化；剪贴板监听不设全局热键（仅面板开关 + 托盘开关）。
- FR-5.7 应用自身为取词而模拟复制写入的剪贴板内容、以及随后恢复的原剪贴板内容，均不视为用户新复制内容，不触发剪贴板监听翻译。

### FR-6 入口四：截图识别

- FR-6.1 交互流：按全局快捷键（出厂 Alt+S）→ 进入框选态（见 FR-8）→ 松开鼠标确认选区 → 系统离线 OCR（Windows.Media.Ocr）提取文字 → 结果在翻译面板（识别形态）中展示纯文字。
- FR-6.2 识别结果区：提供语种下拉，更换语种可对同一选区重新识别；文字可编辑、可复制。
- FR-6.3 截图识别不依赖 API Key，未配置 Key 时完全可用（OCR 在本机完成）。
- FR-6.4 所需 OCR 语言包未安装：明确报错并提供微软官方语言包获取指引链接（见 EX-6）。
- FR-6.5 识别结果区提供"一键送翻译"控件：点击后将识别出的文本按当前活动场景发起翻译并在面板展示译文（Q6 已裁决采纳）。

### FR-7 入口五：截图翻译

- FR-7.1 交互流：按全局快捷键（出厂 Alt+D）→ 框选（同 FR-8）→ 松开确认 → OCR 提取文字 → 提取结果自动按当前活动场景送翻译 → 翻译面板同时展示识别出的原文与流式译文。
- FR-7.2 识别文本为空（选区内无可识别文字）：面板提示"未识别到文字"，不发起翻译请求。
- FR-7.3 未配置 API Key：OCR 照常执行，翻译环节转配置引导（同 FR-3.4）。

### FR-8 截图框选交互（截图识别 / 截图翻译共用）

- FR-8.1 触发后进入全屏框选态：所有显示器覆盖暗色遮罩，光标变为框选样式；拖拽形成的选区内高亮透亮、选区外保持暗色。
- FR-8.2 松开鼠标即确认选区，无需额外交互。
- FR-8.3 框选过程中按 Esc 立即取消，屏幕恢复正常且不产生任何后续动作。
- FR-8.4 多显示器：每个显示器独立覆盖遮罩，可在任意一个显示器上独立完成框选。
- FR-8.5 仅单击未形成有效拖拽面积：视为无效选择，退出框选态（技术负责人复核采纳）。
- FR-8.6 框选过程不在磁盘留下永久截图文件。

### FR-9 翻译面板行为

- FR-9.1 翻译面板是承载原文与译文的弹出小窗；划词、输入、剪贴板监听共用同一面板形态；截图识别 / 截图翻译的结果复用该面板形态并附加各自功能区（语种下拉 / 译文区），布局由 UI/UX 设计规范定义。
- FR-9.2 失焦即隐：默认开启，面板失去焦点即隐藏；可在设置中关闭，关闭后面板保留直至用户主动关闭（提供可见的关闭控件）。
- FR-9.3 尺寸可调（拖拽边缘），调整结果持久记忆，跨重启生效。
- FR-9.4 面板上常驻展示当前活动场景，并提供一键切换控件（见 FR-2.4）；定向场景下面板提供目标语言临时下拉（见 FR-2.7）。
- FR-9.5 原文区可编辑并支持重译（见 FR-4.2）。
- FR-9.6 并发规则：翻译进行中再次发起新翻译时，中止上一轮请求，面板仅呈现最新一轮结果。

### FR-10 译文呈现模式

- FR-10.1 设置项"译文呈现"，出厂默认"全部流式"。呈现模式确认为两档（Q4 已裁决，request.md"三档"系表述笔误）：
  - **全部流式**：所有译文一律流式增量输出。
  - **分档呈现（短文流式 + 长文整段）**：原文长度小于等于阈值时流式输出；超过阈值时采用整段模式。
- FR-10.2 分档阈值可配置，单位为字符数；出厂默认 **1000 字符**（用户裁决 Q2），计数口径含全部字符（含空白与换行，Q10 按建议执行）。
- FR-10.3 整段模式：等待期间展示等待动效，并同时显示**预估剩余时间**；该数值必须显著标注"预估"字样，不得呈现为精确承诺。估算策略按裁决执行（Q3）：按已生成字符的近期速率外推剩余量。
- FR-10.4 流式输出为增量追加渲染，不得整段闪烁重绘；首字到达后持续平滑推进（体验级验收，见 J 组）。

### FR-11 首次运行引导

- FR-11.1 首次启动（无任何已存配置）时展示引导流程，依次为：(a) 欢迎与产品简介（Alya 是什么、如何呼出）；(b) **隐私告知**：明确说明使用翻译功能时，原文将被发送至所配置的第三方云端服务（出厂为 DeepSeek）；截图识别的 OCR 在本机完成、不上传截图；(c) 配置 API Key（输入框 + 连接验证操作，验证需联网调用一次最小请求）；连接验证失败（Key 错误或网络不可达）时提示失败原因，允许重试验证或跳过，跳过则走 FR-11.3 路径；(d) 完成后进入托盘常驻。
- FR-11.2 隐私告知为必经步骤，用户须能看到方可继续（以明确的下一步交互承接，不以折叠小字带过）。
- FR-11.3 引导允许跳过 API Key 配置；跳过后应用照常驻留，截图识别完全可用。
- FR-11.4 未配置 Key 时触发任何翻译类入口（划词 / 输入 / 剪贴板监听 / 截图翻译）：不发起网络请求，弹出配置引导（含隐私告知要点与 Key 输入入口），补配后本次触发的翻译自动继续执行。
- FR-11.5 引导仅在首次运行出现；已存在有效配置后不再自动弹出。

### FR-12 托盘菜单

托盘图标右键菜单聚合各功能，至少包含：

| 菜单项 | 行为 |
|---|---|
| 当前场景：互译 / 定向（勾选或子菜单） | 展示并切换活动场景 |

## 6. 边界条件与异常情况

总原则：所有异常必须在翻译面板错误态或系统通知中呈现，说明可理解的失败原因与下一步动作（重试 / 检查设置 / 查看指引）；禁止静默失败，禁止以空译文或滞留的等待动效冒充成功。

| 编号 | 异常场景 | 触发条件 | 预期表现 |
|---|---|---|---|
| EX-1 | 无网络 / 网络不可达 | 翻译请求发出但无法建立连接 | 面板错误态提示"网络连接失败"，提供重试操作；不崩溃、不停留在无限等待 |
| EX-2 | API Key 无效 | 服务端返回鉴权失败（如 401 类） | 面板提示"鉴权失败，请检查 API Key"，提供打开设置的入口；不重试死循环 |
| EX-3 | 配额 / 余额不足 | 服务端返回余额不足（如 402 类） | 面板提示余额不足，说明需前往服务商控制台处理；不自动重试 |
| EX-4 | 请求超时 | 响应超过时限（30 秒，v1 固定，Q9 已裁决） | 终止请求，面板提示超时并提供重试 |
| EX-5 | 流式传输中断 | 已开始输出后连接中断 | 保留已收到的部分译文，标注"传输中断"并提供重试；不伪装为完整结果 |
| EX-6 | OCR 语言包缺失 | 所选 / 自动词种对应的系统语言包未安装 | 明确报错指出缺少语言包，并提供微软官方语言包获取指引链接；截图识别 / 截图翻译流程就此停止且不误发翻译请求（截图翻译场景同样只提示不翻译） |
| EX-7 | 快捷键注册冲突 | 启动或改键时热键被占用 | 系统通知告知冲突的热键及所属功能；输入翻译、截图识别、截图翻译、场景切换仍可经托盘菜单使用，划词翻译需改键后触发（FR-14.3）；改键成功后热键恢复 |
| EX-8 | 剪贴板非文本内容 | 监听开启期间复制图片 / 文件等 | 静默忽略：不触发翻译、不报错、不打断监听 |
| EX-9 | 空文本触发 | 划词空选区、输入空串回车、截图未识别到文字 | 分别按 FR-3.2 / FR-4.3 / FR-7.2 处理，不发起无效请求 |
| EX-10 | 取词失败 | 模拟复制无返回或超时（部分应用不支持） | 系统通知"未获取到选中文本"；不弹出空面板 |
| EX-11 | 系统安全桌面 | UAC 确认等系统安全桌面处于前台 | 无法取词 / 截屏属预期系统限制；恢复正常桌面后功能可用，无需特殊处理 |
| EX-12 | 重复启动应用 | 已有实例运行时再次启动 | 不创建第二进程，唤起已有实例并呼出输入翻译面板（Q8 已裁决） |
| EX-13 | 翻译中再次触发 | 上一轮未结束又发起新请求 | 中止旧请求，仅呈现最新一轮结果（FR-9.6） |
| EX-14 | 服务端异常响应 | 服务端返回 HTTP 5xx / 非 JSON 响应 / 流内 error 事件 | 面板错误态提示"翻译服务返回异常"，提供重试操作；不自动重试死循环、不静默失败 |

## 7. 数据、权限与兼容性影响

**本地数据**
- 设置与偏好保存在本地；不持久化翻译原文与译文（v1 无历史记录，见第 3 章非目标 9）。
- API Key 用户提供，本地加密存储（既定倾向 Windows DPAPI，最终方案由安全工程师评审确认）；设置界面以掩码展示，不得明文回显，不得写入日志、工件或诊断输出。

**隐私与告知义务**
- 原文发送第三方云端的告知义务：首次运行引导必经告知（FR-11.2），且设置页 AI 服务分区常驻同等提示。
- 截图识别的 OCR 在本机完成，不上传截图；仅当用户执行截图翻译时，识别出的文字作为原文发送翻译服务。

**凭据纪律**
- 真实 DeepSeek API Key 仅由用户提供用于真机验证；任何工件、代码、测试脚本、日志中不得出现真实凭据。

**权限影响**
- 以普通用户权限运行，不要求管理员权限；开机自启经操作系统认可的启动项机制实现，仅在该开关开启时写入。
- 网络访问仅限用户配置的翻译服务端点；无遥测上报。

**兼容性**
- 目标平台：Windows 10 x64 及以上版本与 Windows 11。
- 多显示器与 DPI 缩放：框选遮罩、面板弹出位置须在各 DPI 缩放下正确（验收 I 组抽查 100% 与 150% 缩放）。
- OCR 能力依赖系统已装语言包，缺失时走 EX-6 分支。

## 8. 验收标准

以下各项均为人工可执行步骤 + 预期结果。环境基线：Windows 10/11 x64 真机、用户提供 DeepSeek API Key（真机联调阶段注入，不落盘到任何工件）。

**A 组：安装、首启与常驻**
- A1 运行 NSIS 安装包，按向导安装成功，桌面 / 开始菜单入口正常，安装后可启动。
- A2 解压便携版 zip 至任意目录，运行主程序可直接使用。
- A3 首次启动出现引导流程：欢迎 → 隐私告知（含"原文将发送至第三方云端服务"明确表述）→ Key 配置（可跳过）→ 完成进入托盘。
- A4 点击引导中的"跳过"：应用正常进入托盘常驻，此时执行截图识别完全可用，执行划词翻译触发配置引导（FR-11.4）。
- A5 应用运行中再次双击主程序：不出现第二个实例，已有实例被唤起。
- A6 关闭翻译面板后应用仍在托盘；托盘菜单"退出"后进程结束、托盘图标消失。

**B 组：双场景模型**
- B1 全新安装后触发任意翻译：按互译提示词行为输出（中文→英文、英文→中文）。
- B2 面板一键切到定向并选"日文"，依次用划词、输入、复制、截图翻译四种方式触发：译文均为日文（活动场景全局共用）。
- B3 切到定向后重启应用：活动场景仍为定向，面板目标语言下拉回落为设置页默认值（英文）。
- B4 按 Alt+W：互译 ↔ 定向往返切换，面板场景指示随之变化，下一次翻译立即生效。
- B5 定向 + 目标语言"中文(简体)"翻译一段英文：译文为简体中文，且无解释性文字混入（提示词约束生效）。

**C 组：划词翻译**
- C1 在记事本选中一句英文，按 Alt+Q：约 0.5s 内面板在鼠标附近弹出（本地耗时，不含模型首字），原文正确，译文流式出现。
- C2 选中一段中文按 Alt+Q：译文为英文。
- C3 不选任何文本按 Alt+Q：无面板弹出，出现"未获取到选中文本"通知。

**D 组：输入翻译**
- D1 按 Alt+E：面板出现，焦点在原文输入区；输入英文回车，译文流式输出。
- D2 译文出来后修改原文再回车：按新原文重新翻译，译文区替换为新结果。
- D3 空白内容回车：不发起请求，无错误提示。

**E 组：剪贴板监听**
- E1 开启面板左上角开关，在任意软件 Ctrl+C 一段文本：面板自动展示其译文；托盘菜单勾选态与设置页同步显示"开"。
- E2 保持开关开启重启应用：监听仍为开。
- E3 复制一张图片：无任何反应；随后复制文本：正常触发（监听未被破坏）。
- E4 关闭开关后再复制文本：不再触发翻译。

**F 组：截图识别 / 截图翻译**
- F1 按 Alt+S：全屏（含副屏）覆盖暗色遮罩；拖拽框选一段文字，松开鼠标立即确认，面板展示识别出的纯文字。
- F2 框选过程中按 Esc：立即退出，屏幕恢复正常，无任何结果产生。
- F3 双显示器环境下分别在主屏、副屏各做一次框选：均正常。
- F4 在识别结果面板切换语种下拉（如英文→中文）：对原选区重新识别且结果更新。
- F5 按 Alt+D 框选外文文字：面板同时出现识别原文与流式译文，译文语种符合当前活动场景。
- F6 在设置中将 OCR 语种固定为系统未装语言包的语种并执行截图识别：出现缺语言包报错及微软官方指引链接（EX-6）。
- F7 断网状态下执行截图识别：照常出文字（OCR 离线可用）。
- F8 截图识别出文字后，点击识别结果区"一键送翻译"控件：面板进入翻译流程，按当前活动场景流式输出译文，译文语种符合活动场景（FR-6.5）。
- F9 框选纯空白 / 无文字区域并松开确认：面板提示"未识别到文字"，不发起翻译请求（FR-7.2 / EX-9）。

**G 组：AI 服务配置与异常分支**
- G1 设置页修改接口地址 / 模型名后翻译仍正常（指向另一 OpenAI 兼容端点时行为一致）。
- G2 断网发起翻译：出现"网络连接失败"+ 重试（EX-1）。
- G3 填入错误 Key 发起翻译：出现"鉴权失败，请检查 API Key"（EX-2）。
- G4 使用余额耗尽的 Key：出现余额不足提示，无自动重试（EX-3）。
- G5 翻译中途人为断网：已输出部分保留并标注"传输中断"（EX-5）。

**H 组：面板行为与呈现模式**
- H1 面板失焦后自动隐藏；在设置关闭"失焦即隐"后，点击其他窗口面板保留，可通过关闭控件收起。
- H2 拖拽改变面板尺寸后重启应用：尺寸保持。
- H3 译文呈现切为"分档呈现"、阈值设小（便于测试），翻译一段短文：流式输出；翻译一段超阈值长文：出现等待动效 + 标注"预估"的剩余时间，完成后整段展示。
- H4 翻译进行中立刻再次触发翻译：旧请求中止，仅显示最新结果（EX-13）。

**I 组：托盘、快捷键与兼容性**
- I1 托盘右键菜单逐项可用：场景切换、输入翻译、截图识别、截图翻译、剪贴板监听勾选、设置、退出。

- I3 在设置中依次修改五个快捷键并逐一实测触发正常；设置重启后保持。

- I5 主题切至亮色 / 暗色 / 跟随系统：界面随之变化，重启后保持。
- I6 开启设置页"开机自启"开关后重启系统：应用自动启动并驻留托盘；关闭开关后再次重启系统：不再自启（FR-1.5）。

**J 组：性能与隐私**
- J1 划词触发到面板弹出：本地耗时 < 500ms（不含模型响应；以秒表 / 录屏帧数抽测多次取常规值）。
